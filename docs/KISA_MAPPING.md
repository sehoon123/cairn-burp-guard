# KISA 관련 주제 응용 매핑 — 공식 정본/전체 검증 미수행

**개정일: 2026-11-03 / 주제 매핑 v2.** 이 문서는 **허가된 웹 테스트 계획·한정 발견·비파괴 확인·보고**에서 누락을 드러내기 위한 **주제별 응용(thematic adaptation)** 이다. main `native-pi-ko`는 능동 프로필이며 별도 `native-pi-ko-offline`은 대상 요청0의 로컬 증거/fixture 검토 옵션이다. 이 문서/개발 검증 자체에서는 실제 대상 요청을 하지 않았다. KISA 공식 체크리스트/항목코드의 전재나 일대일 매핑이 아니며, 적합성·인증·취약점 분석·평가 완료를 주장하지 않는다. 이 작업에서는 **공식 PDF 본문/전체 항목을 검증하지 못했다**. 아래 로컬 주제 ID는 전부 이 프로젝트에서 만든 비공식 별칭이다.

## 1. 1차 공식 출처와 참조 판의 확인 수준

| 구분 | 공식 출처/URL | 판/버전 및 확인 수준 |
|---|---|---|
| 발행기관 1차 출처 | 한국인터넷진흥원(KISA), <https://www.kisa.or.kr/> | 공식 기관의 공개 홈페이지. 이전 task-11은 HTTPS 인증서 검증 실패로 본문 미확인을 기록했다. 이번 개정은 재조회하지 않았다. |
| KISA 공개 보안 가이드 자료실 진입 URL | <https://www.kisa.or.kr/2060204> | 문서 탐색용 공식 도메인 URL. 이전 기록에서도 페이지 내용/개별 문서 링크는 미검증이며 이번 개정도 재조회하지 않았다. 특정 PDF의 영구 링크라고 주장하지 않는다. |
| 참조를 의도한 문헌 | KISA의 「주요정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드」 **2021년판을 참조 판 후보로 명시** | **후보 판, 원문 미검증**. 정확한 표지 명칭/발행연도·개정일/최신성/웹 분야 공식 항목/페이지/정본 해시는 이 작업에서 대조하지 못했다. 2021 표기를 검증된 서지 사실이나 최신판 주장으로 사용하지 않는다. |
| 관련 공식 보안 공지 출처(가이드 대체 아님) | KISA KrCERT/CC, <https://www.krcert.or.kr/> | 공식 공지 출처 식별용. 이번 개정에서도 해당 사이트의 가이드 판/본문이나 공지 내용을 조회·검증하지 않았다. |

이전 task-11의 접근 관찰 기록: `https://www.kisa.or.kr/`에 대한 TLS 인증서 검증이 `unable to get local issuer certificate`로 실패했다고 보고했다. 이번 템플릿 개정은 외부 요청 없이 그 미검증 상태를 유지하며 이를 직접 재현한 관찰로 주장하지 않는다. PDF URL/본문에 도달한 결과가 아니며, KISA 서버 장애·문서 부재·PDF 삭제를 뜻하지 않는다. 인증서 검증을 끄거나 비공식 미러를 정본으로 대체하지 않았다. 따라서 **정확한 공식 코드·순서·전체 항목 수·페이지를 기재하지 않는다**. 존재를 확인하지 못한 PDF 다운로드 URL도 지어내지 않는다.

공식 PDF를 직접 확인하지 못한 상태를 숨기기 위해 OWASP/CWE 등의 번호를 KISA 코드처럼 붙이지 않는다. 이 매핑의 버전은 **프로젝트 주제 매핑 v2(2026-11-03), 공식 가이드와의 대조 상태 미검증**이다. 나중에 정확한 공식 판을 확인하더라도 그 사실이 이 세션의 실제 검증으로 소급되지는 않는다.

## 2. 이 프로필이 할 수 있는 일과 할 수 없는 일

- main은 사람이 정확한 origin(scheme/host/port)·경로·GET/HEAD·query·read-only·유효시간·예산을 승인한 유한 계획만 수행한다. 작은 공개 페이지/링크 발견, 상태·보안 헤더·콘텐츠형 관찰, 명시 승인된 비실행 텍스트 표식 비교를 지원한다. 승인 밖 링크/redirect는 발견 후보로만 기록한다. 계획/허가가 없으면 `blocked`와 승인 필요 초안이지 자동 실행이 아니다.
- 기본/최대 **intent20요청·120초(2분)·worker당 동시성1**, 마지막20초 보고용, <=5 고정 슬롯·전체<=100요청, 최소1초간격, 재시도0·자동redirect0이다. 실패/차단/불명도 시도 전 ledger에서 소비한다. 미할당 예산·새 reason turn은 추가 허가가 아니다. bootstrap도 같은 고정 계획 안이다.
- bash의 curl/Python은 **기존 scheme별 상속 proxy 환경만** 사용한다. proxy 부재/충돌/연결 실패/TLS 오류는 중단, 직접 fallback/다른 경로 없음. curl -q FIRST, 상속값 명시 --proxy, --noproxy ''로 NO_PROXY 우회 없음, verified TLS 유지, 환경/CA/설정 변경 없음. 환경만으로 전체 egress 강제를 보장하지 않는다.
- **인증 자동화/세션 작업은 제외**다. 로그인·자격증명 제출·쿠키/JWT/Authorization 주입·갱신·계정 전환·세션 재개·로그인/재로그인 안내가 없다. 401/403/로그인 이동·인증 의존 항목은 `blocked`/`untested`, 사유 `auth_unavailable`로 기록한다.
- Native Pi 내장 도구만 사용한다. MCP/Pi 확장/에이전트 제어 API/Burp 제어 API, Burp UI·규칙·승인·scope·속도·캡처된 바이트 조작, 차단 우회 안내가 없다. 파괴/상태변경·업로드·exploit/SQL·명령실행/traversal·DoS/부하·자격증명 공격·계정 열거·광범위 fuzzing은 금지다.
- **별도 offline-fixture**는 사람이 제공한 가림 로컬 JSON/HAR·합성 fixture만 읽고 대상 요청0/재시도0/네트워크 동시성0이다. 능동 웹 확인 Goal을 이 모드로 조용히 대체하지 않는다.
- 한국어 보고서는 계획·실제 발견/검증·미수행·blocked/auth_unavailable·출처·불확실성을 포함한다. 이번 개발에서 공식 PDF 전체 대조, 능동 HTTP 요청, 실제 대상/Pi/dispatcher/Burp 통합, report-file E2E, 전체 egress enforcement는 **미수행/미검증**이다.

## 3. 로컬 주제 매핑(공식 항목코드 아님)

아래는 일반적인 웹 보안 검토 주제를 보고서에 빠짐없이 표시하기 위한 응용이다. **어느 행도 확인한 KISA 공식 항목의 정확한 번역/동일성/요구사항을 주장하지 않는다.** 제목/범위의 공식 대응은 미확인이다. 표본/한정된 능동 확인/정적 증거에 단서가 없다고 취약점 부재를 뜻하지 않는다.

| 프로젝트 로컬 주제 ID | 비공식 주제 | 허용되는 한정 검토 | 하지 않는 검증/권장 기본 상태 |
|---|---|---|---|
| `LOCAL-INPUT` | 입력 처리/주입 위험 단서 | 명시 승인된 query의 비실행 텍스트 표식 비교 또는 기존 가림 표본의 입력/오류 관찰 | 공격 payload·SQL/명령실행·입증 안 함. 승인 없으면 `blocked`/`untested`, 가림으로 판단 불가면 `inconclusive`. |
| `LOCAL-OUTPUT` | 출력/오류 메타데이터 단서 | 승인 공개 응답의 최소 가림 출력/오류 메타데이터와 대안 출처 기록 | 브라우저 스크립트 실행·저장형 공격 재현 안 함. 생략된 HTML/text로 안전/취약 추정 금지. |
| `LOCAL-FILE` | 공개 경로/파일 처리 단서 | 승인된 공개 페이지/링크/콘텐츠형 발견, 기존 가림 증거 기록 | 미승인 링크 fetch·민감파일 추출·업로드·실행·traversal 안 함. 발견은 접근통제 검증과 다름. |
| `LOCAL-CONFIG` | 서버/전송/보안 메타데이터 | 승인 GET/HEAD의 status/header/content-type 및 verified TLS 실패를 제한 관찰 | 광범위 TLS probe·설정 변경 안 함. 헤더 부재/한 표본만으로 전체 적합성/취약 확정 금지. |
| `LOCAL-DATA` | 정보 단서/증거 최소화 | 제한 메모리 검사 후 가림/생략/truncation/출처, 증거 ID 기록 | 원본 자격증명·개인정보 저장/브라우저·세션 저장소 접근 금지. 가림만으로 노출 여부 입증 불가. |
| `LOCAL-ACCESS` | 접근 통제 관련 커버리지 | 허가된 익명 공개 경로의 status와 401/403/로그인 이동에서 `auth_unavailable` 중단 보고 | 권한/계정 변경·우회·세션 재생·복구 안 함. 인증 의존 범위 `blocked`/`untested`. |
| `LOCAL-SESSION-EXCLUDED` | 인증/세션 동작 — 명시적 제외 | 제외 사유와 커버리지 손실·auth_unavailable만 기록 | 로그인/세션 복구/주입/갱신/계정 전환/재로그인 안내 없음. `blocked`/`untested`; 취약 판정 아님. |
| `LOCAL-AVAILABILITY` | 고정 예산/차단/실패 출처 | 20요청·2분·동시성1/<=5슬롯·<=100, 실제 시도 ledger, 실제 관찰한 revision/disposition/reason 기록 | 부하/스트레스·예산 환급/재시도 없음. local451/BLOCKED·proxy/TLS 실패·미응답은 대상 취약점 아님. |

`FORWARDED`는 네이티브 전송 해제만 의미한다. 대상 도달/처리 성공을 입증하지 않는다. export의 `statusCode`만으로 응답 출처를 추정하지 않는다. 다른 확장, TLS pass-through, raw CONNECT/WebSocket, 직접 소켓 등 callback 밖 트래픽은 이 증거의 보장 밖이다. HAR/JSON은 가림 처리 사본이지 전체 wire capture가 아니다. 상세 계약은 [INTERFACES.md](INTERFACES.md)를 따른다.

## 4. 결과 언어와 증거 기준

| 상태 | 이 문서에서의 뜻 | 금지되는 비약 |
|---|---|---|
| `observed` | 특정 좁은 사실을 승인 확인의 관찰 또는 제공 증거에서 확인 | 관찰 자체를 취약 확정으로 바꾸기 |
| `not_observed` | 검토한 한정 표본에서 그 현상이 보이지 않음 | 취약점 부재/안전/적합 보장 |
| `blocked` | 정책·허가·프로필 경계 때문에 수행하지 않음 | 차단에서 `vulnerable` 추정, 우회/접근 복구 권고 |
| `untested` | 입력·시간·범위 등의 부족으로 미수행 | 수행/안전/취약으로 둔갑 |
| `inconclusive` | 가림·잘림·누락·출처 불명으로 결론 불가 | 모호한 단서에서 확정 판정 |

심각도/영향/신뢰도는 별도 근거가 있을 때만 평가한다. CVSS/공식 KISA 항목코드를 만들어 내지 않는다. 각 행에 증거 ID, 정책 revision(실제 관찰 때만), 가림/누락/잘림, worker HTTP 관찰/Guard 원문 callback export(평문 비밀 가능, 보고서에 복사 금지)/합성 fixture의 출처 구분, 관찰과 해석, 실제 알려진 예산 사용량(불명은 `unknown`), 커버리지·blocked·auth_unavailable·불확실성, 종료 사유를 남긴다. 실제 대상 이름/원본 로그/개인·세션·자격증명은 포함하지 않는다.

## 5. 보고서 완료 게이트와 공식 검증의 구분

모든 실행 가능한 정상/부분/차단/오류/conclude 반환 경로에서 한국어 보고서와 확인표를 저장·읽기 확인한다. 실제 Goal 충족과 최종 `report.ko.md`/`checklist.ko.md` 저장·읽기 확인 전에는 `complete`를 반환하지 않는다. 미수행 테스트 Goal을 계획/차단 보고만으로 완료했다고 하지 않는다. multi-intent는 사람이 기존 CAIRN UI에서 bootstrap을 끈 계획을 사용한다. bootstrap execute 성공은 전체 프로젝트 완료 계약이므로 계획 전달을 위해 fact-only execute/고의 timeout/소스 변경을 만들지 않는다. 강제 종료/쓰기 실패/conclude 미실행은 프롬프트가 최종화를 보장할 수 없으며 체크포인트만 남을 수 있다. [CAIRN_TEMPLATES.md](CAIRN_TEMPLATES.md)의 한계를 따른다.

정확한 공식 항목 대조를 했다고 기록하려면 적어도 아래 정보가 **실제로 확인되어야** 한다. 이는 이후 원문 검토에 필요한 서지/증거 조건이며 현재 완료한 작업이 아니다.

- [ ] 공식기관 원문 URL/제목/표지의 발행연도·개정판/접근일/정본 식별 정보를 확인했다.
- [ ] 해당 판의 웹 관련 실제 항목명·코드·페이지를 직접 대조했다(변형한 로컬 ID와 구분).
- [ ] 공식 항목 중 제외·미수행·가림으로 판단 불가한 범위와 사유를 유지했다.
- [ ] 공식 문서 읽기, template unit/loader 검증, 실제 동작/대상 시험을 별개로 기록했다.
- [ ] 종합 보고서에 **공식 전체 검증 미수행/적합성 미판정**을 지우지 않고, 실제 확인한 좁은 범위만 갱신했다.

현재 위 정본 대조/전체 검증은 모두 **미수행**이다. Python 검증기가 성공해도 이 표의 공식 원문 확인이나 보안 적합성 검증이 이루어지는 것은 아니다.
