# Native Burp adapter

`dev.cairnguard.GuardExtension` owns the human Swing tab, project-local storage, a **data-free original-object Proxy continuation handler**, and a Montoya `HttpHandler`. Only `ToolType.PROXY` requests are protected; other tools continue with their original objects. No network sender, Burp admin interface, worker API, login or session management is added.

## Native identity and bounded inspection

Allowed requests, responses and annotations are the **same native objects**, not reconstructions. No `with*`, annotation changes, Host correction, HTTP/2 pseudo-header normalization, URL normalization, decompression or payload rewriting is performed. The extension does not infer complete wire equality from an inspection copy.

Scope uses **`httpService().host()/port()/secure()` and the untouched `request.path()` (path/query)**. It never trusts `request.url()` or Host/`:authority` for the transport authority. Explicit URL rules therefore inspect the **actual-service URL**, not a Host-derived authority. An actual out-of-scope service remains blocked even if Host claims an allowed one. A fuzzed, absent or duplicate Host/`:authority` is not an unconditional rejection.

All-path scope permits `/c/;/main.do`, `/c/%2e/main.do`, nested percent/matrix/separator variants and malformed-percent targets unchanged. Decoded/normalized aliases belong only to internal scope/rule/availability matching; they never replace the native request target. Restricted path scope must verify its bounded routing views. Authored health/response-limit routes remain strict exact routes; this is not a traffic sanitizer.

Capture is complete (no capture quota): every header, the full body and the untouched native target are copied for evidence regardless of size or inspection-slot availability. **Policy inspection** limits remain bounded: essential method/service/path validity, 256 headers / 64 KiB header text and a 1 MiB body for rule inspection, 128 protected callback slots, 8 optional inspection slots with no native-flight/correlation admission quota. Policy-uninspectable content (oversize, no free slot → `<FIELD>_INSPECTION_UNAVAILABLE_INSPECTION_CAPACITY`, unsupported charset/encoding/multipart) is reported unavailable, **not an automatic451**, and the copy's `headersComplete`/`bodyComplete` flags stay truthful (false only for genuine native read failures). No oversized zero-filled body sentinel is shown as original data. Content rules are demand-driven and cannot grant a content-dependent EXEMPT from unavailable inspection. Explicit inspectable operator BLOCK rules still apply. Essential scope uncertainty and enforcement capacity still fail closed.

The complete native target, including the full query, is retained by the capture and shown/exported unchanged; there is no shorter raw-display truncation. Only optional **policy query inspection** is separately bounded: a query longer than the policy URL limit makes that inspection unavailable (`REQUEST_TOO_LARGE`) rather than matching a truncated prefix. The inspection string is never a transmit target. An independently verified zero-length body stays EMPTY even when optional policy inspection is unavailable; an unknown or omitted nonempty body never qualifies as a health probe. Health requires exact configured GET, no query, verified EMPTY body and ordinary scope/rules, and bypasses only operator pause.

Every screen and output (request history, approvals, response-only unpaired rows, schema-2 JSON/HAR, incident JSON, human JSON/HAR/incident files) shows **original** inspection copies with **no masking and no collection/retention/export quota**, labeled **inspection copy, not wire proof**; they keep structured header lists and complete body bytes plus the actual-service route (never the fuzzed Host) and the original metadata until clear/project change/unload. Memory grows without bound (OOM is a documented, user-managed risk) and every output may contain plaintext credentials. A missing original is shown as unavailable. The schema-2 HAR uses the human HAR's faithful-URL rule: `_rawTarget`/`_service` come from the retained capture route, the standard `url` is filled only when that untouched target is a faithful ordinary URL, otherwise it is empty with `_urlUnavailable` and the retained `_displayUrl` (display text, not a target claim); without a retained route nothing is guessed (`NO_SERVICE_ROUTE`). The human JSON/HAR/incident buttons write originals only after a per-file plaintext consent, from a lock-time snapshot with serialization and file work outside locks, a final pre-rename check and no size cap. Status/log fields stay payload-free categorical counters. Nothing feeds worker/control surfaces or automatic policy harvesting. Project epoch changes, clear and close dispose the data; a clear before the final export check aborts that export. A declared charset or header set that was omitted, over-long or ambiguous leaves a body as bytes (HEX/base64), never as verified text.

## Listener boundary and OFF

**The user explicitly DEFERRED per-port protection H. Current scope protects ALL Proxy listeners; H is not a current gate or PASS.** Restricted attribution remains unsupported (historical H failed). Human settings/whole-policy JSON reject creating or replacing a nonempty restriction; old values survive unrelated edits, and explicit clearing requires confirmation of all-Proxy protection. Native Community2026.10.1 exposed distinct Proxy/HTTP callback IDs; the pinned2026.7 API gives no documented shared identity. Original-annotation identity also failed. The production `ListenerObserver` now only continues original requests/annotations: it does **not read IDs/listener/content or populate any trusted registry**. Registration order is lifecycle wiring, not identity proof. Deregistration still handles initialization failures and synchronous unload. See [exact-artifact findings](V2_NATIVE_FINDINGS.md).

Before content capture, `HttpHandler` calls `controller.nativeMode(messageId)`:

* Human-confirmed global OFF returns a project/revision-bound, count-only bypass token first.
* Empty `guardListenerPorts` protects all Proxy listeners normally.
* Every configured restriction currently yields **data-free `LISTENER_UNVERIFIED`** before native content capture, for selected AND unselected ports. UI explicitly warns; this is a mitigation, not H acceptance.
* Core trusted-registry/unselected-token behavior is exercised with synthetic supplied proof only. There is no supported native producer. It must never be fed cross-namespace numeric equality, annotation identity/values, timing/FIFO/content fingerprints or destination-port guesses.

OFF/unselected paths create no new evidence, approval, pacing, watcher/budget state or response association. Content-free used-ID tombstones (including OFF numeric IDs) are retained only to prevent mispairing, never admission. Untracked responses do not even read native response status/body-length scalars. Existing protected response associations may finish logging across OFF/unselected traffic; they own no native permit. Bypass construction is non-sending and its token is rechecked at final return; stale generation/project/shutdown cannot smuggle an old bypass; reused IDs alone do not deny traffic. See [PASSTHROUGH.md](PASSTHROUGH.md).

The previous observer/HTTP ID assumption was **falsified, not merely untested**. Both native listeners now reject without target arrivals; fixed omission placeholders can be recorded, never their original native contents. Core registry tests are not native evidence. A supported identity/design resolution is required before H can pass; normal HTTP-handler request/response flight correlation is separate and is not replaced.

## Final handoff and local denial

Protected pipeline: mode/slot checks → complete copy + optional bounded inspection → actual-service policy/evidence → explicit ASK approval → authored pacing/queue → **construct non-sending original-object continuation** → atomic project/revision/pause/policy/shutdown and intent commit → evidence-only ID association → return original continuation.

No watcher check/claim/ticket, native Permit, configured native concurrency, response timeout quarantine or correlation100 cap remains. Prior5xx/oversize/fan-out/slow/missing callbacks cannot block/pause new policy-allowed requests. No master/reason toggle substitutes for removal. Factory null/throw, stale project/policy and explicit budget failure still fail closed before new intent spend. Use the actual CommitResult reason. No adapter proves target delivery from a returned continuation, retries uncertain dispatch or infers native completion.

Local HTTP451 preserves these original JSON keys **in their original order**:

```json
{"source":"cairn-proxy-guard","outcome":"blocked","reason":"PAUSED","evidenceId":"00000000-0000-4000-8000-000000000001","retryable":false,"guardState":"PAUSED_BY_OPERATOR","local":true,"policyRevision":7}
```

The appended guard state/revision come from typed `controller.denial`; append `overlayId` only for a valid opaque UUID. Reason/state/ID alphabets and numeric revision are independently bounded; no note inference, exception messages, host/path/tags or configurable serializer enters the local body. Native spoof failure falls back to drop, never allow. A target's unrelated451 is still an upstream response, not a local guard block.

## Response correlation is observational only

Never-reused Proxy IDs may pair a response with the exact retained protected original. Missing/unreadable/reused IDs do not deny otherwise allowed traffic. Used-ID tombstones persist content-free until handler unload, even after a paired response or clear; numeric OFF IDs carry no contents or response association. Reuse is permanently ambiguous, not “latest wins.” Unreadable IDs may make protected response provenance unavailable; never guess.

When still-retained protected-only provenance establishes the evidence epoch but not which request produced a response, capture the complete supplied response as an explicitly **UNPAIRED_RESPONSE** row. No request method/URL/hits/tags/revision is borrowed from an older request. Full headers/body/status/byte length stay original across raw/JSON/HAR; raw request is null and exports label unavailable correlation. Unpaired counters are separate from local/upstream because even response origin can be ambiguous. Missing/unknown, OFF/mixed, wrong-tool, cleared/old-project and post-shutdown callbacks cannot attach or resurrect originals. No completion or native ownership is fabricated. There is no native-completion-dependent admission resource to release or time out.

For eligible captured responses, native status and body().length() are independently observed, never inferred from Content-Length. The seven-argument response bridge preserves native scalars/completeness flags even if the content copy fails. Unknown size is-1, not a fake zero. Full response copies need no optional inspection slot. Requests/responses/annotations continue as the exact original native objects regardless of logging availability. See [evidence/export semantics](EVIDENCE.md).

## Owned external fixture clients

`scripts/native_burp_smoke.py` is **external test code**, not bundled extension logic or a control plane. It starts numeric-loopback-only owned fixtures and uses external clients through an already human-configured disposable Burp. It never loads/configures Burp, changes protection/policy/listeners, reads credentials, or calls any admin API. All request values are synthetic. Do not run it against a user's live project. No automatic URL-normalizing client: Python `http.client` preserves target spelling; curl reproductions must use **`--path-as-is`**.

Historical runner phases require a fresh disposable profile and explicit human preconditions. **Do not run retired heavy/circuit/fanout or native-concurrency/quarantine phases as current acceptance:** the runner is preserved test/archival code, not adapted into a new live-Burp experiment in this task.
