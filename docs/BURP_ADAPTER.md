# Native Burp adapter

`dev.cairnguard.GuardExtension` owns the human Swing tab, project-local storage, a **data-free original-object Proxy continuation handler**, and a Montoya `HttpHandler`. Only `ToolType.PROXY` requests are protected; other tools continue with their original objects. No network sender, Burp admin interface, worker API, login or session management is added.

## Native identity and bounded inspection

Allowed requests, responses and annotations are the **same native objects**, not reconstructions. No `with*`, annotation changes, Host correction, HTTP/2 pseudo-header normalization, URL normalization, decompression or payload rewriting is performed. The extension does not infer complete wire equality from an inspection copy.

Scope uses **`httpService().host()/port()/secure()` and the untouched `request.path()` (path/query)**. It never trusts `request.url()` or Host/`:authority` for the transport authority. Explicit URL rules therefore inspect the **actual-service URL**, not a Host-derived authority. An actual out-of-scope service remains blocked even if Host claims an allowed one. A fuzzed, absent or duplicate Host/`:authority` is not an unconditional rejection.

All-path scope permits `/c/;/main.do`, `/c/%2e/main.do`, nested percent/matrix/separator variants and malformed-percent targets unchanged. Decoded/normalized aliases belong only to internal scope/rule/availability matching; they never replace the native request target. Restricted path scope must verify its bounded routing views. Authored health/response-limit routes remain strict exact routes; this is not a traffic sanitizer.

Capture is complete (no capture quota): every header, the full body and the untouched native target are copied for evidence regardless of size or inspection-slot availability. **Policy inspection** limits remain bounded: essential method/service/path validity, 256 headers / 64 KiB header text and a 1 MiB body for rule inspection, 128 protected callback slots, 8 optional inspection slots and 100 protected native flights. Policy-uninspectable content (oversize, no free slot → `<FIELD>_INSPECTION_UNAVAILABLE_INSPECTION_CAPACITY`, unsupported charset/encoding/multipart) is reported unavailable, **not an automatic451**, and the copy's `headersComplete`/`bodyComplete` flags stay truthful (false only for genuine native read failures). No oversized zero-filled body sentinel is shown as original data. Content rules are demand-driven and cannot grant a content-dependent EXEMPT from unavailable inspection. Explicit inspectable operator BLOCK rules still apply. Essential scope uncertainty and enforcement capacity still fail closed.

The complete native target, including the full query, is retained by the capture and shown/exported unchanged; there is no shorter raw-display truncation. Only optional **policy query inspection** is separately bounded: a query longer than the policy URL limit makes that inspection unavailable (`REQUEST_TOO_LARGE`) rather than matching a truncated prefix. The inspection string is never a transmit target. An independently verified zero-length body stays EMPTY even when optional policy inspection is unavailable; an unknown or omitted nonempty body never qualifies as a health probe. Health requires exact configured GET, no query, verified EMPTY body and ordinary scope/rules, and bypasses only operator pause/circuit.

Every screen and output (request history, approvals, automatic-block rows, large-response candidates, schema-2 JSON/HAR, incident JSON, human JSON/HAR/incident files) shows **original** inspection copies with **no masking and no collection/retention/export quota**, labeled **inspection copy, not wire proof**; they keep structured header lists and complete body bytes plus the actual-service route (never the fuzzed Host) and the original metadata until clear/project change/unload. Memory grows without bound (OOM is a documented, user-managed risk) and every output may contain plaintext credentials. A missing original is shown as unavailable. The schema-2 HAR uses the human HAR's faithful-URL rule: `_rawTarget`/`_service` come from the retained capture route, the standard `url` is filled only when that untouched target is a faithful ordinary URL, otherwise it is empty with `_urlUnavailable` and the retained `_displayUrl` (display text, not a target claim); without a retained route nothing is guessed (`NO_SERVICE_ROUTE`). Candidate/overlay drafts and exceptions are seeded only from that trusted original through an opaque per-request source reference and are persisted only by an explicit reviewed save that the controller revalidates after every confirmation. The human JSON/HAR/incident buttons write originals only after a per-file plaintext consent, from a lock-time snapshot with serialization and file work outside locks, a final pre-rename check and no size cap. Status/log fields stay payload-free categorical counters. Nothing feeds worker/control surfaces or automatic policy harvesting. Project epoch changes, clear and close dispose the data; a clear before the final export check aborts that export. A declared charset or header set that was omitted, over-long or ambiguous leaves a body as bytes (HEX/base64), never as verified text.

## Listener boundary and OFF

**The user explicitly DEFERRED per-port protection H. Current scope protects ALL Proxy listeners; H is not a current gate or PASS.** Restricted attribution remains unsupported (historical H failed). Human settings/whole-policy JSON reject creating or replacing a nonempty restriction; old values survive unrelated edits, and explicit clearing requires confirmation of all-Proxy protection. Native Community2026.10.1 exposed distinct Proxy/HTTP callback IDs; the pinned2026.7 API gives no documented shared identity. Original-annotation identity also failed. The production `ListenerObserver` now only continues original requests/annotations: it does **not read IDs/listener/content or populate any trusted registry**. Registration order is lifecycle wiring, not identity proof. Deregistration still handles initialization failures and synchronous unload. See [exact-artifact findings](V2_NATIVE_FINDINGS.md).

Before content capture, `HttpHandler` calls `controller.nativeMode(messageId)`:

* Human-confirmed global OFF returns a project/revision-bound, count-only bypass token first.
* Empty `guardListenerPorts` protects all Proxy listeners normally.
* Every configured restriction currently yields **data-free `LISTENER_UNVERIFIED`** before native content capture, for selected AND unselected ports. UI explicitly warns; this is a mitigation, not H acceptance.
* Core trusted-registry/unselected-token behavior is exercised with synthetic supplied proof only. There is no supported native producer. It must never be fed cross-namespace numeric equality, annotation identity/values, timing/FIFO/content fingerprints or destination-port guesses.

OFF/unselected paths create no new evidence, approval, rate permit, watcher/budget state or response correlation. Untracked responses do not even read native response status/body-length scalars. Existing protected flights still complete their own permits and evidence across OFF/unselected traffic. Bypass construction is non-sending and its token is rechecked at final return; stale generation/project/shutdown/collisions cannot smuggle an old bypass. See [PASSTHROUGH.md](PASSTHROUGH.md).

The previous observer/HTTP ID assumption was **falsified, not merely untested**. Both native listeners now reject without target arrivals; fixed omission placeholders can be recorded, never their original native contents. Core registry tests are not native evidence. A supported identity/design resolution is required before H can pass; normal HTTP-handler request/response flight correlation is separate and is not replaced.

## Final handoff and local denial

Protected pipeline: mode/ID/slot checks → bounded inspection + policy/evidence → human approval without permit → rate/concurrency permit → **construct non-sending original-object continuation** → install bounded flight → atomic `commitDetailed` (watcher before intent) → immediately return continuation.

Factory null/throw, local correlation capacity, stale policy/project, final watcher/fanout or budget rejection never consumes a new intent quota or creates a successful watcher flight. Use the **actual `CommitResult.reason()`**, not generic `FINAL_CHECK_REJECTED`. Factories can reenter; preparing/flight ownership prevents ambiguous IDs from completing/replacing an earlier protected request. A duplicate ID is dropped, not spoofed as a response that could release an older permit. No adapter can prove that returning a native continuation means wire delivery; accounting is final accepted native handoff, never a delivery claim or automatic refund after uncertain dispatch.

Local HTTP451 preserves these original JSON keys **in their original order**:

```json
{"source":"cairn-proxy-guard","outcome":"blocked","reason":"PAUSED","evidenceId":"00000000-0000-4000-8000-000000000001","retryable":false,"guardState":"PAUSED_BY_OPERATOR","local":true,"policyRevision":7}
```

The appended guard state/revision come from typed `controller.denial`; append `overlayId` only for a valid opaque UUID. Reason/state/ID alphabets and numeric revision are independently bounded; no note inference, exception messages, host/path/tags or configurable serializer enters the local body. Native spoof failure falls back to drop, never allow. A target's unrelated451 is still an upstream response, not a local guard block.

## Responses and permit lifetime

A matching actual Proxy response closes only its own native permit, independently of capture or continuation-factory failure. Missing/timeout responses retain permits; shutdown and logical watcher deadlines never manufacture native completion. Stalled permits quarantine their host and still count toward global concurrency. Late and duplicate responses cannot release other permits.

On tracked responses, native status and `body().length()` are observed independently of the content copy and independently of each other. No full-body copy or attacker-provided Content-Length is used to measure actual bytes. The seven-argument `controller.response(..., actualBytes, headersComplete, bodyComplete)` bridge preserves scalars even when a body copy is unavailable. Unknown size is `-1`, never a fake zero or declared length. Response content is copied completely and needs no inspection slot; the first large response cannot be prevented, and originals/annotations continue unchanged.

## Owned external fixture clients

`scripts/native_burp_smoke.py` is **external test code**, not bundled extension logic or a control plane. It starts numeric-loopback-only owned fixtures and uses external clients through an already human-configured disposable Burp. It never loads/configures Burp, changes protection/policy/listeners, reads credentials, or calls any admin API. All request values are synthetic. Do not run it against a user's live project. No automatic URL-normalizing client: Python `http.client` preserves target spelling; curl reproductions must use **`--path-as-is`**.

Each phase requires the human UI to set its preconditions, separately, in a fresh disposable profile. Existing manual recipes predating v2 may have obsolete broad delete/unsupported-payload assumptions; use the following current phase contracts:

| Phase | Human precondition / external observation |
| --- | --- |

Fuzzed Host also names an owned loopback endpoint so proxy routing mistakes cannot send to a private/external target. |
| `heavy` | Per-path max5MiB, other detectors not interfering. First `/large` returns exact6MiB, next is local typed heavy451. Script waits for a **human UI overlay release** and Enter, then verifies another6MiB. It does not release the overlay itself. |

All denial phases validate the local source marker **plus `local:true`, typed guardState and numeric policyRevision**. They also assert zero new fixture arrivals. The fixture records the raw request line (not the standard library's normalized `self.path`), exact body bytes and Host for owned equality assertions. An upstream parser rejection is not a local451; the owned raw Java fixture specifically accepts malformed-percent bytes to prove handoff independent of a generic URI parser.

`python3 -m unittest discover -s scripts -p test_native_burp_smoke.py` checks fixture/client assertions and direct owned socket behavior, **not native Burp**. JUnit adapter/lifecycle tests use Mockito/native-action seams; `runtime/ProxyLoopbackTest` uses a bounded raw loopback fixture and the real controller. Keep these distinct from a real Burp smoke, exact final-JAR validation, release or independent review. Main alone performs native acceptance in a fresh profile; historical results elsewhere do not certify this v2 candidate.
