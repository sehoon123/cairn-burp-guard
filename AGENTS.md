# Cairn Proxy Guard — project rules

- This is a NEW standalone Burp extension. Do not edit the existing MCP bridge, CAIRN source, installed Burp binaries, desktop settings, or unrelated repositories.
- User-approved MVP: passive-to-worker Proxy safety controller; no MCP server, Pi extension, agent-control API, login, cookie/JWT injection, session refresh, or account management. Allowed requests/responses must remain byte-for-byte untouched by this extension.
- Java 21, Gradle wrapper, Montoya 2026.7, Jackson 2.22.4, RE2/J 1.8. No Java backtracking regex on traffic. No arbitrary code execution or outbound network requests from the extension.
- Latest user requirements (2026-11-04): scope uses the ACTUAL destination service host/scheme/port and request path, not a possibly fuzzed Host/:authority header. Do not reject an in-scope request merely for Host-header mismatch, unsupported body/charset/encoding, malformed payload, or optional content-capture limits. Content inspection is best-effort for explicitly authored rules; report unavailable inspection, do not silently pretend it passed. Scope uncertainty, policy/project validity, approval/queue timeout, enforcement capacity and shutdown still fail closed. Empty allowlist allows nothing. New EXEMPT beats ordinary BLOCK/ASK rules, never hard scope/lifecycle or automatic safety/budget/rate gates.
- Latest path requirement (2026-11-04): ALL-path scope must allow pentest targets such as `/c/;/main.do`, `/c/%2e/main.do`, dot/matrix/separator variants and encoded spellings. Never impose a blanket `AMBIGUOUS_PATH` sanitizer before scope or normalize/rewrite the forwarded request. Bounded raw/decoded/normalized aliases are INTERNAL scope/rule/overlay views only. Restricted path scope must cover known routing views; undecodable/deep variants can pass explicit all-path scope with `PATH_INTERPRETATION_INCOMPLETE`, never prove a restricted path scope or grant a path-dependent EXEMPT. Explicit operator BLOCK rules, destination scope, blocked path constraints and availability limits still apply. Keep authored health/response-limit route configuration strict and exact; do not mistake relaxed TRAFFIC acceptance for accepting ambiguous health-probe configuration.
- The user explicitly requested temporary human-only ALL Proxy passthrough (2026-11-04): a separately confirmed, persistently visible protection-OFF state, not an Allow rule or pause. It skips scope/rules/inspection/approval/rate for NEW native Proxy callbacks, captures no new request/response contents, and keeps only a count. Runtime-only, project/revision checked, reset on project change/restart/unavailability. Cancel old waits without approving them; retain old in-flight permits. Native failures/shutdown/stale transitions still fail closed. No worker control surface.
- Bound memory, request inspection, response capture, pending approvals, and queues. The user explicitly requested UNMASKED human request-history display (2026-11-04). Keep a SEPARATE bounded, project-bound, memory-only unmasked UI capture with explicit truncation/omission labels; do not serialize it into evidence/export/logs or expose it to workers. Exportable evidence remains redacted; never automatically persist/export raw credentials. Config may contain operator-authored patterns, but never automatically harvest secret values into it.
- Configuration changes are local human UI actions. Workers do not receive Burp control tools. Authentication state must never be changed by this extension.
- Keep API contracts in `docs/INTERFACES.md`. Coordinate changes to shared models; own only the paths assigned in a task.
- The user explicitly authorized a NEW PUBLIC GitHub repository and ongoing development. Publish only reviewed source/docs, synthetic fixtures, and intended build artifacts to the verified project remote. Never publish local paths, credentials, license/activation data, private targets, original logs/screenshots, or unrelated changes. No release/completion claims without corresponding evidence.
- The user explicitly authorized experiments with the installed Burp. Use a separate temporary test profile/project, loopback-only owned fixture servers, and synthetic credentials. Never alter a user's live project or copy activation data. Do not bypass activation/licensing; if the temporary instance needs user activation, report that blocker rather than circumventing it.
- Separate unit/adapter/loopback results from real Burp smoke. Never claim native integration was run if it was not. Keep private runtime artifacts outside Git and clean up only processes/files created by this task.
